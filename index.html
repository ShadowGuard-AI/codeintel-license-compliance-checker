Entered in the Book

It reads a project's dependencies. It finds the licence reported for each one. It prints a list. It marks some entries for a human to look at.

Names from the Requirements File

A requirements.txt in the project directory wins. Its lines are read first. Comments are cut. Blank lines pass. Lines starting with a dash are skipped, so an included file line is not read as a package. A name is taken up to the first version mark, extras bracket, or environment marker. A version is recorded only where the line pins one with a double equals sign. Otherwise the version stands as unspecified.

No Requirements File Means a Report About This Machine

No requirements.txt. Then a warning is printed. Then the current environment is reported instead, from pip freeze. That report describes the environment, not the project. A freeze that fails ends the run. Exit 1.

One Package at a Time

One pip show per package. In order. Slow in direct proportion to the list. The pip used is this interpreter's own pip, run as a module. Not a bare pip found on the path. A different Python would give a different shop's stock. The licence line is taken first. Failing that, the licence expression line, held in the code as License-Expression. Failing both, the entry stands as UNKNOWN. A home page is kept only where one is actually printed.

Flagged Means Look

UNKNOWN is flagged, with the reason that no licence was reported for the package. An empty licence is flagged the same way. A licence string containing AGPL, LGPL, GPL, MPL, EPL, or CDDL is flagged, and the reason given names the family found and advises checking its conditions before use. Flagged means look. It does not mean forbidden. It does not mean judged.

A Mention Is Flagged Like a Grant

Matching is by substring. A licence text that merely mentions one of those names while saying it does not apply is flagged all the same. The code states this choice plainly. A human sorts the mention from the grant.

The Count at the Foot

Text form: one block per package, with package, version, licence, homepage, and a flagged line where a flag applies. Last line: a count, Flagged, so many of so many packages need a compliance look, with the flagged names listed after it. Json form: one entry per package, carrying its details and a compliance flag field, held in the code as compliance_flag, holding either the reason or nothing, with a final count entry added under its own key. The report is printed even where packages are flagged. The run then exits normally. A flag never becomes an exit code.

# codeintel-License-Compliance-Checker

Scans a project's dependencies and lists their licenses, highlighting potential compliance issues. An entry is flagged in the report when its license is UNKNOWN (pip reported no license) or when its license string contains a copyleft family name: GPL, LGPL, AGPL, MPL, EPL, or CDDL. The report ends with a summary count of flagged entries. Flagging marks an entry for a human compliance look, it is not a judgement that the license cannot be used. - Focused on Tools for static code analysis, vulnerability scanning, and code quality assurance

## Install

`git clone https://github.com/ShadowStrikeHQ/codeintel-license-compliance-checker`

## Usage

`./codeintel-license-compliance-checker [params]`

## Parameters

- `-h`: Show help message and exit

- `--output_format`: No description provided

- `--log_level`: Set the logging level.
